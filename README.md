# むろらんグルメマップ

室蘭のまだ知らない飲食店を発見するための、チーム G07 の Web アプリです。
Python / Django のテンプレートによるサーバーサイドレンダリングを採用しています。

## 実装済みの機能

- Django プロジェクト `config` と、担当別の5アプリを作成・登録
- SQLite、日本語表示、タイムゾーン `Asia/Tokyo` の設定
- 共通のヘッダー・フッター・テンプレート、レスポンシブなトップ画面
- 依存バージョンの固定、基本テスト、GitHub Actions によるチェック
- 担当 A: トップ → メールアドレスでのログイン／新規登録 → 探し方の選択
- 登録後の自動ログイン、POST によるログアウト、未ログイン時のアクセス制限
- ログイン後の共通ヘッダー・下部ナビゲーション
- ジャンル選択・マップ検索への遷移と、ログイン必須のマップ仮画面
- 担当 B: 05ジャンル選択・06店舗一覧・07条件検索・09店舗詳細
- 店舗名・キーワード・ジャンル・予算・エリア・特徴タグの組み合わせ検索
- Django Admin による店舗・分類・画像の登録、架空の10店舗のデモ投入

地図・経路・口コミ・お気に入り・訪問履歴・スタンプの本格機能、
プロフィール編集・パスワード再設定・メール到達確認は未実装です。
ゲスト利用はありません。スタンプ・お気に入り・マイページは、下部ナビゲーションで
操作できない「準備中」として表示します。

## 必要なもの

- Python 3.12 以上（今回の動作確認は Python 3.12）
- Git
- 推奨環境: Windows 11 + WSL Ubuntu + VS Code

SQLite は Python 標準の `sqlite3` を使うため、別途 DB サーバーは不要です。
画像の検証に Pillow を使用します（requirements.txt に含みます）。Node.js や API キーは不要です。

## ローカル起動手順（WSL Ubuntu / Linux / macOS）

以下は WSL の Ubuntu ターミナルなどで実行します。

### 1. リポジトリを取得する

```bash
git clone https://github.com/potatotipus/muroran-gourmet.git
cd muroran-gourmet
```

PR のレビュー中は、店舗検索機能のブランチに切り替えてください。

```bash
git switch feat/restaurant-search
```

すでに取得済みの場合は、そのチェックアウトを利用してください。
マージ後は `main` で同じ手順を実行できます。

### 2. 仮想環境を作成・有効化する

```bash
python3 -m venv .venv
source .venv/bin/activate
python --version
```

WSL Ubuntu で `venv` が見つからない場合は、Python のバージョンを確認して
対応する `python3-venv` パッケージをインストールしてください。
ターミナルを開き直した場合は `source .venv/bin/activate` を再実行します。

### 3. 依存ライブラリを導入する

```bash
python -m pip install -r requirements.txt
```

`requirements.txt` は Django 5.2 LTS と、その依存ライブラリの動作確認済み
バージョンを固定しています。更新時はテストも実行してください。

### 4. データベースを初期化する

```bash
python manage.py migrate
```

プロジェクト直下に `db.sqlite3` が作成され、Django 標準の認証・セッションなどの
テーブルが初期化されます。同じコマンドは繰り返し実行できます。
`restaurants/0001_initial` で店舗・ジャンル・特徴タグを追加し、
`0002_search_categories` で6つの料理ジャンルと6つの特徴タグを初期登録します。
既存の認証テーブル・アカウントを削除・差し替えする処理はありません。
DB、仮想環境、秘密情報は Git に登録しません。

### 4-2. デモ店舗を投入する（動作確認用）

```bash
python manage.py seed_restaurants
```

「サンプル食堂01」など、架空と分かる10店舗を登録します。
住所・位置・営業時間・価格・店主紹介・メニューはすべてデモ用で、画面にも明示します。
実店舗の写真・口コミ・評価は追加しません。画像なしの店舗には共通プレースホルダーを表示します。

コマンドは何度実行しても重複しません。`demo_key` という専用の一意キーで判定し、
既存のデモ店舗・特徴タグの割り当て・管理画面での編集を上書きせず、通常登録の店舗も変更しません。
削除されたデモ店舗だけは、次の投入で再作成されます。

### 5. 開発サーバーを起動する

```bash
python manage.py runserver
```

ローカルのブラウザで `http://127.0.0.1:8000/` を開きます。
トップ画面から「新規登録」に進み、ユーザー名（表示名）・メールアドレス・パスワード・
確認用パスワードを入力してください。登録すると自動ログインし「探し方の選択」が表示されます。
「ジャンルから探す」→「すべて」で10店舗が表示されます。店舗カードから詳細を開けます。
「条件で絞り込む」から予算・ジャンル・エリア・特徴を指定し、検索できます。
「地図から探す」は引き続き準備中の仮画面です。
ヘッダーからログアウト後、登録したメールアドレスとパスワードで再ログインできます。
終了は `Ctrl+C`、仮想環境の終了は `deactivate` です。

### 管理画面を使う場合（任意）

```bash
python manage.py createsuperuser
```

開発サーバーを起動し、`http://127.0.0.1:8000/admin/` にアクセスします。
管理者の認証は Django 標準機能です。一般利用者向けのログイン機能とは別です。
管理画面の「店舗情報・検索」から、店舗・料理ジャンル・特徴タグを追加・編集できます。
店舗画像は掲載許可のある JPEG・PNG・WebP（5MB以内）を登録してください。
画像は `media/` に保存し、Git には登録しません。開発時のみ Django が画像を配信します。
本番での画像配信・バックアップは別途設定してください。
初期タグの識別子 `one-coin`、`cheap`、`large`、`late-night` は検索ロジックと共有するため維持してください。
新しいジャンル・タグの識別子には、重複しない英数字・ハイフンを入力してください。
一般利用者が新規登録しても、管理者権限は付与されません。

## VS Code での動作確認（Windows 11 + WSL Ubuntu）

1. WSL のリポジトリ直下で `code .` を実行し、WSL のフォルダーとして開きます。
2. コマンドパレットの「Python: Select Interpreter」で `.venv/bin/python` を選びます。
3. VS Code のターミナルで `source .venv/bin/activate` を実行します。
4. `python -m pip install -r requirements.txt`、`python manage.py migrate`、
   `python manage.py seed_restaurants` を順に実行します。
5. `python manage.py runserver` を実行し、ブラウザで `http://127.0.0.1:8000/` を開きます。
6. 新規登録／ログイン → 探し方の選択 → ジャンル → 一覧 → 詳細を確認します。
   一覧から条件検索を開き、予算1,000円以内・カレー・中島・テイクアウトで検索すると
   「サンプルカレー店02」が表示されます。条件画面への戻りとリセットも確認できます。

仮想環境を有効化し、リポジトリ直下で実行してください。

```bash
python -m pip check
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test --verbosity 2
```

テストではトップ画面・共通テンプレート・静的ファイル・環境変数に加え、
登録とパスワードのハッシュ化・重複メール・不正な入力・認証エラー・無効ユーザー・
画面遷移・ログアウト・CSRF・表示名のエスケープ・未ログイン時のアクセス制限を確認します。
店舗側は、全件／ジャンル／タグ／キーワード／複合条件の検索、検索条件の維持・リセット、
該当なし・詳細の404、画像・欠損値の扱い、管理画面、データ制約、デモ再投入を検証します。
テスト用 DB は Django が自動作成・破棄し、ローカルの `db.sqlite3` を変更しません。
GitHub Actions でも、依存導入・マイグレーション・上記チェックを実行します。

## ディレクトリと担当範囲

```text
muroran-gourmet/
├── config/          # 全体設定、ルーティング、トップ画面
├── accounts/        # A: アカウント・ユーザー管理（forms / views / urls / tests / templates）
├── restaurants/     # B: 店舗情報・検索
├── maps/            # C: 地図・経路案内
├── community/       # D: 口コミ・お気に入り
├── visits/          # E: 訪問履歴・スタンプ
├── templates/       # base.html、home.html、includes/
├── static/css/      # 共通スタイル
├── tests/           # 基本テスト
├── requirements.txt
└── manage.py
```

| アプリ | 今後の責務 | データ・依存関係の方針 |
| --- | --- | --- |
| `accounts` | 認証、ユーザー管理、探し方の選択 | Django 標準 User と標準認証バックエンドを利用する |
| `restaurants` | 店舗情報、ジャンル、検索 | 店舗データの管理元を一本化する |
| `maps` | 店舗の地図、経路案内、自分のマップ | 店舗位置は `restaurants`、訪問状態は `visits` から参照する |
| `community` | 口コミ、お気に入り | ユーザーと店舗を参照する |
| `visits` | 訪問履歴、スタンプ、ポイント | ユーザーと店舗を参照する |

| 05 ジャンル選択 | `/restaurants/genres/` | `restaurants:genres` | ログイン必須 |
| 06 店舗一覧 | `/restaurants/` | `restaurants:list` | ログイン必須 |
| 07 条件検索 | `/restaurants/filters/` | `restaurants:filters` | ログイン必須 |

ログイン後のページにはキャッシュ抑止を設定しています。

## アカウントのデータ設計

既存の SQLite DB と Django 標準 `auth.User` を維持し、モデルの差し替えや
既存データのリセットは行いません。アカウント機能の認証仕様・モデルは変更していません。

- ログインにはメールアドレスを使い、前後の空白を除去して小文字に統一します。
- 新規登録では `User.email` と、一意制約のある `User.username` の両方に同じ
  正規化済みメールアドレスを保存します。標準の `ModelBackend`、パスワード検証・
  ハッシュ化、セッション管理をそのまま利用します。
- 入力欄「ユーザー名」は表示名で、`User.first_name` に保存します。表示名は重複可能です。
  メールアドレスと表示名は各150文字以内です（標準 `username` の上限に合わせています）。
- メールアドレスの重複はフォームで検証し、同時登録時も `username` の一意制約で拒否します。
- Django 管理コマンドなどで従来のユーザー名を使って作った管理者は、引き続きその
  ユーザー名で `/admin/` にログインできます。一般画面でのメールログインも必要な場合は、
  管理者作成時の `username` にも小文字のメールアドレスを指定してください。
- 他担当のモデルでユーザーを参照するときは `settings.AUTH_USER_MODEL`、Python コードでは
  `get_user_model()` を利用し、表示名には `get_short_name()` を使ってください。

## 店舗モデルと次の担当者への引き継ぎ

| モデル | データと関係 |
| --- | --- |
| `Genre` | 料理ジャンル。名前・一意の識別子・表示順を管理 |
| `Tag` | 店舗の特徴。名前・一意の識別子・表示順を管理 |
| `Restaurant` | 店名、説明、住所、地区、緯度経度、ジャンル、価格帯、営業時間、定休日、店主紹介、メニュー、画像、特徴タグ、デモ管理キー |

`Restaurant.genre` は `Genre` への外部キーで、使用中ジャンルの削除は `PROTECT` で防ぎます。
`Restaurant.tags` は `Tag` との多対多です。「ワンコイン」はジャンルではなくタグ、
「激安大盛り」は `cheap` と `large` の両タグで表します。
ジャンルや価格などが未登録の場合も表示でき、画像ファイルが欠落した場合にもプレースホルダーへ切り替えます。

緯度・経度は小数点以下6桁の Decimal で、両方入力または両方未登録にします。
緯度は-90〜90、経度は-180〜180、価格は非負で最高価格≧最低価格とし、DB制約でも保護します。
`maps` は `restaurants.models.Restaurant` の位置情報を参照してください。デモの位置は架空です。
口コミ・お気に入り・訪問履歴も `Restaurant` の主キーを外部キーで参照し、店舗情報を複製しないでください。
店舗詳細の URL は `restaurant.get_absolute_url()` から取得できます。

## 検索条件の仕様

- SQLite に対して Django ORM の部分一致検索を行います。キーワードは店舗名・説明・住所・
  エリア・ジャンル名・タグ名・店主紹介・メニューを対象とし、空白で分けた複数語はすべての語に一致させます。
- 予算は**価格帯の上限**が500／1,000／1,500円以内の店舗です。上限未登録の店舗は除外します。
  最安メニューだけを根拠に、価格帯全体が予算内だとは判定しません。
- 選択したジャンル・エリア・予算・すべての特徴タグを AND で組み合わせます。
  エリアは高砂・中島・本町に加えて、店舗に登録された他の地区を選べます。
- 営業時間のリアルタイム判定はありません。「夜遅くまで営業」は管理者が確認して付ける特徴です。
  管理画面では営業時間も必須とし、検索時も営業時間未登録の店舗は除外します。
- 検索条件は GET の `q`・`genre`（識別子）・`budget`・`area`・複数の `tags`（識別子）です。
  一覧・条件画面・詳細・戻るリンクで引き継ぎ、画面間のセッション共有には依存しません。
  「条件をリセットする」で全条件を解除できます。不正な条件はエラー表示し、全件検索へ黙って変更しません。

## 環境変数と注意点

| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| `DJANGO_DEBUG` | `1` | 開発時のみ `1`。`0` でデバッグ無効 |
| `DJANGO_SECRET_KEY` | 開発専用の固定値 | 開発以外では秘密鍵を環境変数で指定する |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]` | 許可ホストをカンマ区切りで指定する |

ローカル開発では追加設定なしで起動できます。必要なら `export DJANGO_ALLOWED_HOSTS=...`
などで指定してください。`.env` ファイルの自動読み込みは行いません。
`DJANGO_DEBUG=0` で秘密鍵が未指定の場合は、起動エラーにします。

この設定と `runserver` は開発用です。本番公開の際は、専用の設定・秘密鍵・HTTPS・
静的ファイルの配信方法などを別途整備し、`check --deploy` を実行してください。
静的ファイル収集先は `staticfiles/` で、Git の対象外です。
