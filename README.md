# むろらんグルメマップ

室蘭のまだ知らない飲食店を発見するための、チーム G07 の Web アプリです。
Python / Django のテンプレートによるサーバーサイドレンダリングを採用しています。

## 実装済みの機能

- Django プロジェクト `config` と、担当別の5アプリを作成・登録
- SQLite、日本語表示、タイムゾーン `Asia/Tokyo` の設定
- 共通のヘッダー・フッター・テンプレート、レスポンシブなトップ画面
- 依存バージョンの固定、基本テスト、GitHub Actions によるチェック
- 担当 A: トップ → メールアドレスでのログイン／新規登録 → 探し方の選択
- 登録後の自動ログイン、POST によるログアウト、未ログイン時のアクセス制限
- ログイン後の共通ヘッダー・下部ナビゲーション
- ジャンル選択・マップ検索への遷移と、ログイン必須の仮画面

店舗検索・地図・口コミ・お気に入り・訪問履歴・スタンプの本格機能、
プロフィール編集・パスワード再設定・メール到達確認は未実装です。
ゲスト利用はありません。スタンプ・お気に入り・マイページは、下部ナビゲーションで
操作できない「準備中」として表示します。

## 必要なもの

- Python 3.12 以上（今回の動作確認は Python 3.12）
- Git
- 推奨環境: Windows 11 + WSL Ubuntu + VS Code

SQLite は Python 標準の `sqlite3` を使うため、別途 DB サーバーは不要です。
Node.js や API キーも、この初期構築では不要です。

## ローカル起動手順（WSL Ubuntu / Linux / macOS）

以下は WSL の Ubuntu ターミナルなどで実行します。

### 1. リポジトリを取得する

```bash
git clone https://github.com/potatotipus/muroran-gourmet.git
cd muroran-gourmet
```

PR のレビュー中は、アカウント機能のブランチに切り替えてください。

```bash
git switch feat/accounts-user-management
```

すでに取得済みの場合は、そのチェックアウトを利用してください。
マージ後は `main` で同じ手順を実行できます。

### 2. 仮想環境を作成・有効化する

```bash
python3 -m venv .venv
source .venv/bin/activate
python --version
```

WSL Ubuntu で `venv` が見つからない場合は、Python のバージョンを確認して
対応する `python3-venv` パッケージをインストールしてください。
ターミナルを開き直した場合は `source .venv/bin/activate` を再実行します。

### 3. 依存ライブラリを導入する

```bash
python -m pip install -r requirements.txt
```

`requirements.txt` は Django 5.2 LTS と、その依存ライブラリの動作確認済み
バージョンを固定しています。更新時はテストも実行してください。

### 4. データベースを初期化する

```bash
python manage.py migrate
```

プロジェクト直下に `db.sqlite3` が作成され、Django 標準の認証・セッションなどの
テーブルが初期化されます。同じコマンドは繰り返し実行できます。
独自アプリにはまだモデルがないため、独自のマイグレーションはありません。
DB、仮想環境、秘密情報は Git に登録しません。

### 5. 開発サーバーを起動する

```bash
python manage.py runserver
```

ローカルのブラウザで `http://127.0.0.1:8000/` を開きます。
トップ画面から「新規登録」に進み、ユーザー名（表示名）・メールアドレス・パスワード・
確認用パスワードを入力してください。登録すると自動ログインし「探し方の選択」が表示されます。
「ジャンルから探す」「地図から探す」は、それぞれの準備中画面に遷移します。
ヘッダーからログアウト後、登録したメールアドレスとパスワードで再ログインできます。
終了は `Ctrl+C`、仮想環境の終了は `deactivate` です。

### 管理画面を使う場合（任意）

```bash
python manage.py createsuperuser
```

開発サーバーを起動し、`http://127.0.0.1:8000/admin/` にアクセスします。
管理者の認証は Django 標準機能です。一般利用者向けのログイン機能とは別です。
現段階では独自の店舗などのデータ登録機能はありません。
一般利用者が新規登録しても、管理者権限は付与されません。

## チェックとテスト

仮想環境を有効化し、リポジトリ直下で実行してください。

```bash
python -m pip check
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test --verbosity 2
```

テストではトップ画面・共通テンプレート・静的ファイル・環境変数に加え、
登録とパスワードのハッシュ化・重複メール・不正な入力・認証エラー・無効ユーザー・
画面遷移・ログアウト・CSRF・表示名のエスケープ・未ログイン時のアクセス制限を確認します。
テスト用 DB は Django が自動作成・破棄し、ローカルの `db.sqlite3` を変更しません。
GitHub Actions でも、依存導入・マイグレーション・上記チェックを実行します。

## ディレクトリと担当範囲

```text
muroran-gourmet/
├── config/          # 全体設定、ルーティング、トップ画面
├── accounts/        # A: アカウント・ユーザー管理（forms / views / urls / tests / templates）
├── restaurants/     # B: 店舗情報・検索
├── maps/            # C: 地図・経路案内
├── community/       # D: 口コミ・お気に入り
├── visits/          # E: 訪問履歴・スタンプ
├── templates/       # base.html、home.html、includes/
├── static/css/      # 共通スタイル
├── tests/           # 基本テスト
├── requirements.txt
└── manage.py
```

| アプリ | 今後の責務 | データ・依存関係の方針 |
| --- | --- | --- |
| `accounts` | 認証、ユーザー管理、探し方の選択 | Django 標準 User と標準認証バックエンドを利用する |
| `restaurants` | 店舗情報、ジャンル、検索 | 店舗データの管理元を一本化する |
| `maps` | 店舗の地図、経路案内、自分のマップ | 店舗位置は `restaurants`、訪問状態は `visits` から参照する |
| `community` | 口コミ、お気に入り | ユーザーと店舗を参照する |
| `visits` | 訪問履歴、スタンプ、ポイント | ユーザーと店舗を参照する |

## URL とアクセス制限

| 画面 | URL | URL 名 | アクセス |
| --- | --- | --- | --- |
| 01 トップ | `/` | `home` | 公開（ログイン後は「お店を探す」を表示） |
| 02 ログイン | `/accounts/login/` | `accounts:login` | 公開、ログイン済みなら04へ |
| 03 新規登録 | `/accounts/signup/` | `accounts:signup` | 公開、ログイン済みなら04へ |
| 04 探し方の選択 | `/accounts/choose/` | `accounts:choose` | ログイン必須 |
| 05 ジャンル選択（仮） | `/restaurants/genres/` | `restaurants:genres` | ログイン必須 |
| 08 マップ検索（仮） | `/maps/search/` | `maps:search` | ログイン必須 |
| ログアウト | `/accounts/logout/` | `accounts:logout` | CSRF トークン付き POST のみ |
| 管理画面 | `/admin/` | `admin:index` | Django 標準の管理者認証 |

ログイン・新規登録成功後は必ず04、ログアウト後は01へ移動します。
任意の `next` パラメーターによる遷移先の変更は受け付けません。
未ログインで04・05・08を開くと、ログイン画面に移動します。
ログイン後のページにはキャッシュ抑止を設定しています。

## アカウントのデータ設計

既存の SQLite DB と Django 標準 `auth.User` を維持し、モデルの差し替えや
既存データのリセットは行いません。今回、独自マイグレーションや追加依存はありません。

- ログインにはメールアドレスを使い、前後の空白を除去して小文字に統一します。
- 新規登録では `User.email` と、一意制約のある `User.username` の両方に同じ
  正規化済みメールアドレスを保存します。標準の `ModelBackend`、パスワード検証・
  ハッシュ化、セッション管理をそのまま利用します。
- 入力欄「ユーザー名」は表示名で、`User.first_name` に保存します。表示名は重複可能です。
  メールアドレスと表示名は各150文字以内です（標準 `username` の上限に合わせています）。
- メールアドレスの重複はフォームで検証し、同時登録時も `username` の一意制約で拒否します。
- Django 管理コマンドなどで従来のユーザー名を使って作った管理者は、引き続きその
  ユーザー名で `/admin/` にログインできます。一般画面でのメールログインも必要な場合は、
  管理者作成時の `username` にも小文字のメールアドレスを指定してください。
- 他担当のモデルでユーザーを参照するときは `settings.AUTH_USER_MODEL`、Python コードでは
  `get_user_model()` を利用し、表示名には `get_short_name()` を使ってください。

## 設計上の判断・今後の開発

- `COG仕様書.pdf`、最初の画面遷移図・議事録と依頼文を確認しています。
  今回は担当 A のアカウント機能を実装し、05・08は次段階に引き継ぐ仮画面としました。
- 資料の相違は、今回の依頼を最優先とし、最新の議事録 ＞ 画面遷移図 ＞ COG仕様書で
  判断しました。画面の構成・遷移は画面遷移図を基準にしています。
- PDF の追加機能にあるゲスト閲覧は、今回の「ゲスト機能は実装しない」に従い採用しません。
  PDF のログイン後に一覧を表示する利用例より、今回の04「探し方の選択」への遷移を優先します。
  PDF と議事録では C・D・E の分担に違いがありますが、上記の担当表は最新の議事録を維持します。
- トップ画面を特定の担当アプリに所属させず、`config.views.HomeView` に配置しました。
- 本格的な店舗機能のモデルやデモ店舗は、今回追加していません。
- 共通 UI は `templates/base.html` を継承してください。アプリごとのテンプレートや
  静的ファイルは `restaurants/templates/restaurants/` などの名前空間で分けてください。
- 各担当は機能ごとのブランチで開発し、モデル変更時はマイグレーションを同梱してください。
  他アプリのモデル・URL、共通設定、依存関係の変更は事前に担当者間で調整してください。
- Leaflet / OpenStreetMap や Googleマップ外部リンクは、地図機能の実装時に導入します。
  この画面のイラストは CSS による装飾で、実際の店舗・地図・経路を表しません。

## 環境変数と注意点

| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| `DJANGO_DEBUG` | `1` | 開発時のみ `1`。`0` でデバッグ無効 |
| `DJANGO_SECRET_KEY` | 開発専用の固定値 | 開発以外では秘密鍵を環境変数で指定する |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]` | 許可ホストをカンマ区切りで指定する |

ローカル開発では追加設定なしで起動できます。必要なら `export DJANGO_ALLOWED_HOSTS=...`
などで指定してください。`.env` ファイルの自動読み込みは行いません。
`DJANGO_DEBUG=0` で秘密鍵が未指定の場合は、起動エラーにします。

この設定と `runserver` は開発用です。本番公開の際は、専用の設定・秘密鍵・HTTPS・
静的ファイルの配信方法などを別途整備し、`check --deploy` を実行してください。
静的ファイル収集先は `staticfiles/` で、Git の対象外です。
